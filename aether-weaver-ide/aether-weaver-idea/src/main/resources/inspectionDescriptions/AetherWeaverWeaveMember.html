Reports what a weave's member gets wrong about the target it will end up in.
  • AW1031 — a @Shadow's type is not the one the target gave the member. A shadow is a promise about something that already exists, so its type is not a choice.
  • AW1042 — a static weave's handler that the emitted call could not reach. The class would verify and load; IllegalAccessError arrives at the first execution of the injected call. Comes with a quick fix.
  • AW1080 — a merged member the target already declares.
  • AW1095 — a generated @Accessor or @Invoker whose signature the target already declares.

A @Unique member is deliberately exempt from the collision checks. It may collide: the framework renames it to name$aw$<digest> and reports AW1094, which is information rather than a fault. Everything else merged cannot be renamed, because the weave's own code refers to it by name — so overwriting the target's member is not an option, and would replace working code with an uninitialised copy.

Not reported here: AW1060, two @Redirects on one call site. Deciding it means knowing which bytecode operations each @At actually matched. Two redirects naming the same method and the same target look identical in source and can still land on different sites once ordinals and slices are applied, so a source-level approximation would report correct weaves.
