Reports an @Inject handler whose own signature cannot fit the target method it names.

Three rules, all of them decided by the annotation processor in one place and all of them mistakes people make while the target is perfectly well found:

  • AW1040 — the parameters are not a prefix of the target's. The injected call pushes the target's own arguments in order, so a handler may take the first n of them and nothing else. A Callback, a @Local capture and a static weave's leading target instance are not arguments and do not count.
  • AW1041 — the handler does not return void. The injected call is a statement in the middle of the target's own code, so a returned value would have nowhere to go. To change what the target returns, take a ReturnableCallback and cancel with a value.
  • AW1071 — the ReturnableCallback's type argument is not the target's return type.

AW1040 comes with a fix that adjusts the parameter list to the target while keeping how many arguments the handler asked for, the names it gave them, and every callback and @Local capture.

The inspection stays silent unless the selector names exactly one method the target declares, and unless every type involved resolves. A selector matching several methods is AW1021; a handler compared against the wrong overload would be a confident, specific, false report on correct code, which costs more than the report it replaces.

Not reported here: whether the handler calls cancel() on a void target (AW1070) or reads value() where there is none (AW1072). Those are statements in a method body; the processor declines them for the same reason and the weave-time engine decides them from bytecode.
