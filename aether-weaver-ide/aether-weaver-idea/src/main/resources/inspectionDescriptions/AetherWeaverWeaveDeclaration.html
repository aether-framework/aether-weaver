Reports a @Weave declaration that cannot do what it says, on grounds the source alone settles.

Four rules, each stated in the framework's own API documentation:

  • AW1001 — the weave names no target, so nothing would be woven
  • AW1002 — the weave names its targets twice, as class literals and as names
  • AW1090 — @Shadow in a static weave, whose code never moves into the target and therefore has no reference to be rewritten into
  • AW1091 — @Unique in a static weave, which merges nothing and so has no member to make unique

A handler's own signature — AW1040, AW1041, AW1071 — is the neighbouring inspection Handler signature does not fit the target, because deciding it means resolving the target first.

Deliberately absent from both is everything that needs a compiled body: AW1043, AW1050 and their neighbours. The build reports those, and the annotation processor says out loud (AW1200) when it cannot. An editor approximating them would produce false reports on exactly the shapes injection exists for.
