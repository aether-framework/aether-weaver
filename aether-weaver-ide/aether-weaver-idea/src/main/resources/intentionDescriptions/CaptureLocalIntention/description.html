Generates a weave handler where the local variable under the caret is live, capturing it.

A local exists between two positions in the bytecode, not between two statements, and a @Local naming it outside that range fails the build with AW1050. So wanting a variable has meant working out where it is alive before deciding where to inject. Here the variable chooses the position instead.

Every operation in the method is put to the target's own local variable table, and only the positions where this name resolves are offered, nearest to the caret first. The difference is not one that can be read off the source: in final String tag = text.toString(); the variable is not yet live at that call, and a handler generated there would read perfectly and not work.

A parameter is not offered — a handler's parameter list is already a prefix of its target's, so the value is there and capturing it would be the same thing twice. A target compiled without a local variable table is reported rather than generated for: that is AW1052, and the remedy is -g.
