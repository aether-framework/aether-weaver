Rewrites a desc: selector into the source form that names the same member.

Both spellings are interchangeable by design, and neither is second-class. This converts the one a reader has to decode into the one they can read, without changing which member is named — the result is parsed back and compared before it is offered, so a conversion that would not survive the round trip never appears.

The opposite direction is deliberately absent, and not because of a defect: a source-form selector has no descriptor form until something resolves its types. charge(java.math.BigDecimal) could name class BigDecimal in package java.math or a nested math.BigDecimal inside java, which are different descriptors. MemberSelector does not resolve — that is the engine's job, against a classpath — so it hands such a selector back unchanged, and an intention offering to convert it would change nothing. The plugin could resolve it through PSI and decline to: working out what a selector means in a second place is the one thing this plugin is arranged to avoid, and a descriptor written by the IDE that disagreed with the build's would disagree silently. 

desc:charge(Ljava/math/BigDecimal;)V
becomes 
charge(java.math.BigDecimal):void
